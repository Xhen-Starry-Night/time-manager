## 2. 开发复杂度分析

### 复杂度分级标准

- **低**：纯前端UI，无需后端逻辑或简单状态管理
- **中**：需要Modal组件、文件系统操作、数据转换
- **高**：需要新数据结构、聚合计算、多模块协作

### 功能复杂度评估

| 功能 | 复杂度 | 原因 |
|------|--------|------|
| 搜索框（前端过滤） | 低 | 仅需字符串匹配，已有数据 |
| 待办输入框 + 添加 | 低 | 调用现有 CLI 逻辑 |
| 待办删除 | 低 | 调用现有 CLI 逻辑 |
| 待办完成（复选框） | 低 | 修改 JSON 文件 |
| 待办转日程 | 中 | 需要创建 ICS 文件 |
| 日程 ICS 解析 | 中 | 需要解析 ICS 格式 |
| 新建日程 | 中 | 需要 Modal + 日期输入 |
| 新建卡片按钮 | 中 | 需要 Modal + 路径输入 |
| Obsidian导入按钮 | 中 | 调用现有 CLI 逻辑 + 文件选择 |
| 复习看板右侧详情 | 低 | 复用分类树组件 |
| 开始计时按钮 | 低 | 切换Tab + 触发开始 |
| 重新预测按钮 | 中 | 调用 FSRS 重新计算 |
| 计时停止后链接卡片 | 中 | 需要 Modal + 卡片路径输入 + 记忆表现选择 |
| 右键菜单 | 高 | Iced 右键支持 + 多个菜单项 |
| 学习统计 | 高 | 需要遍历所有 review_records 聚合计算 |

## 4. 开发优先级排序

### 排序原则

1. **用户价值优先**：高频使用功能优先
2. **低复杂度优先**：快速产出可用功能
3. **依赖优先**：基础设施先实现
4. **功能闭环优先**：让核心流程完整

### 优先级分级

| 优先级 | 说明 |
|--------|------|
| P0 | 必须完成，核心功能闭环 |
| P1 | 重要功能，提升可用性 |
| P2 | 增强功能，完善体验 |
| P3 | 可选功能，后续迭代 |

## 8. 风险与建议

### 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Iced 0.14 API 不熟悉 | 中 | 参考官方文档和示例 |
| ICS 解析库缺失 | 低 | 手动解析关键字段 |
| Modal 状态管理复杂 | 中 | 使用单一 Modal 枚举管理 |
| 右键菜单支持有限 | 低 | 可延后实现或使用替代方案 |

### 开发建议

1. **每完成一个 Phase 提交一次**
2. **每个 Phase 内的任务可以并行开发**
3. **优先保证 P0 功能完成**
4. **测试验证每个功能后再进入下一阶段**
