# 《时间管理器（TimeManager）》设计要求

时间管理器（TimeManager）是一个面向知识工作者的时间追踪与 spaced repetition 复习管理系统。系统由 CLI（命令行界面）和 GUI（图形用户界面）两部分组成，共享同一套数据存储层。用户可以通过树形知识分类体系组织学习卡片，使用番茄钟式计时器追踪学习时长，并基于 FSRS 算法预测卡片最佳复习时间。

## 系统功能

### 一、CLI 命令行工具（tmd）

1. 支持数据目录初始化，自动创建预设目录结构和默认配置文件
2. 支持知识树（Tree）的创建和列表查看，基于文件系统实现层级结构
3. 支持学习卡片（Card）的创建、列表查看、预测查看，卡片关联预设参数
4. 支持计时器（Timer）的启动、暂停、停止、查看操作，计时记录持久化到 JSON 文件
5. 支持卡片与计时记录的关联（CardLink），自动触发 FSRS 预测并更新记忆状态
6. 支持预设（Preset）的创建、列表查看、训练（基于已有卡片数据优化 FSRS 参数）
7. 支持待办事项（Todo）的创建、列表查看、完成切换、删除，支持 iCalendar ICS 格式导入/导出
8. 支持日程（Schedule）的创建、列表查看，支持 ICS 格式的解析和生成
9. 支持复习列表查看与急迫度筛选（已过期/今日/三天内）

### 二、GUI 图形界面（tmd-gui）

1. 基于 Iced 框架的桌面图形界面，包含七大标签页：
   - **分类（Category）标签页**：树形知识目录浏览，支持文件夹和卡片的创建、编辑、删除、搜索，支持从 Obsidian 知识库导入目录结构
   - **复习（Review）标签页**：按急迫度显示待复习卡片列表，支持搜索和急迫度筛选，一键开始复习计时
   - **计时器（Timer）标签页**：计时器启动/暂停/停止，学习时长实时显示，计时停止后自动进入链接模式，可关联到现有卡片或创建新卡片，关联时记录记忆质量（重学/困难/好/简单）
   - **日程（Schedule）标签页**：查看和管理日程事件
   - **待办（Todo）标签页**：待办事项的创建、编辑、完成切换、删除，支持优先级、截止日期、标签
   - **预设（Preset）标签页**：预设列表查看、创建编辑、训练触发
   - **设置（Settings）标签页**：数据目录配置、默认预设选择、配置持久化

2. 支持多种模态对话框：新建卡片、计时关联、待办编辑、预设详情、删除确认、错误提示等

### 三、数据存储层

1. 基于 JSON 文件系统的结构化存储，自动创建目录结构（categories/、timers/、presets/、todos/、schedules/）
2. 数据模型包括：卡片（Card）、计时记录（Timer）、预设（Preset）、待办（Todo）、日程（Schedule）、复习记录（ReviewRecord）、记忆预测（Prediction）、递归规则（RecurrenceRule）
3. 配置管理通过 TOML 格式文件，支持环境变量 TMD_CONFIG_DIR 和 TMD_DATA_DIR
4. 错误处理采用 thiserror 自定义错误类型，覆盖 IO、JSON 解析、路径无效、资源未找到等场景

### 四、FSRS 间隔重复算法

1. 集成 FSRS v5 算法库，实现基于记忆稳定性（stability）和难度（difficulty）的复习调度
2. 支持记忆状态的 bytes 序列化与反序列化，实现状态持久化
3. 急迫度计算逻辑：基于距下次复习的天数，分为四级（已过期/今日/3天内/以后）
4. 支持预设级别的自定义 FSRS 参数训练

### 五、Obsidian 知识库导入

1. 支持从 Obsidian Vault 目录导入知识结构
2. Timeignore 规则过滤：支持 .obsidian/、.trash/、.git/ 等默认忽略规则，支持自定义 .timeignore 文件
3. 基于 walkdir 递归遍历，按目录结构映射到 Tree 的知识分类体系

# 《时间管理器（TimeManager）》评价标准

## 分组：1~2人1组

## 评分组成：作品60分 + 设计报告40分

### 一、作品（小组）60分

1. **界面设计：20%**
   - CLI 界面：命令参数设计合理性、帮助信息完整性、输出格式清晰度
   - GUI 界面：标签页布局合理性、交互流畅度、视觉一致性、模态对话框使用恰当性
   - 急迫度可视化：颜色编码（红/黄/绿/灰）区分不同急迫度等级

2. **系统功能完成情况：40%**
   - CLI 命令覆盖度（Init、TreeCreate、CardCreate、TimerStart/Stop、TodoCreate、ScheduleCreate 等）
   - GUI 标签页完整性（7个标签页均需实现并功能完整）
   - 计时器与卡片的关联工作流完整度
   - FSRS 预测与持久化的正确性
   - 数据持久化的完整性与一致性

3. **模块设计：40%**
   - 应用层（app）与 GUI 层（gui）的分离设计
   - 数据层（data）的统一抽象（DataFs + 模型）
   - Timer 状态机设计（Idle→Running→Paused 状态转换）
   - FSRS 预测器的封装与扩展性
   - CLI 与 GUI 共享同一数据层的架构设计

4. **加分/扣分项（5分）**
   - 项目主要功能代码行数超过 2000 行则加 5 分 / 少于 800 行则扣 5 分
   - 备注：加/扣分后，总分数控制在 [0, 60]
   - 当前项目代码量约 4500+ 行（含测试），满足加分条件

### 二、设计报告 40分

1. **系统结构：10%**（标注各人负责模块）
   - 使用层次图或 HIPO 图描述系统总体架构
   - 明确标注 CLI、GUI、Data、FSRS、Timer 等模块的分工

2. **模块设计：40%**（个人）
   - 对本人负责模块进行详细设计，使用软件流程图描述
   - 关键模块需包括：
     - Timer 状态机设计（状态转换图）
     - FSRS 复习预测流程
     - 数据持久化架构设计
     - 卡片-计时器关联工作流

3. **模块测试情况：20%**（个人）
   - 单元测试覆盖：data_fs 操作、FSRS 预测、ICS 解析/生成、Obsidian 导入
   - 集成测试覆盖：完整学习工作流、预设工作流、Todo→Schedule 转换
   - 测试用例需包含边界条件和异常路径

4. **系统调试情况：20%**
   - CLI 命令的端到端测试验证
   - GUI 各标签页的功能验证
   - 数据持久化前后的状态一致性验证

5. **系统实现情况：10%**
   - Rust 语言特性和生态运用（Serde、Iced、Clap、Chrono）
   - 编码风格一致性（命名规范、错误处理模式、模块划分）
   - 文档完整性（README、配置文件说明、使用说明）

6. **加分/扣分项（5分）**
   - 正文中采用 4 种以上软件工程涉及的图形化数据工具则加 5 分
   - 要求在软件总体设计部分必须用层次图或 HIPO 图描述
   - 软件详细设计中必须用软件流程图描述
   - 否则最高扣 5 分
