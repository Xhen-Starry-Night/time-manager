# 第 1 章 项目设计需求与小组分工

## 1.1 项目设计需求

### 1.1.1 问题定义

知识工作者在学习过程中面临两个核心问题：第一，难以精确追踪在不同知识点上的学习时间投入；第二，缺乏科学的方法来规划复习计划，导致遗忘曲线无法有效干预。现有的时间管理工具（如 Toggl、RescueTime）与间隔重复工具（如 Anki）相互独立，数据无法打通。

时间管理器（TimeManager）旨在将时间追踪与间隔重复复习管理整合为统一系统，让用户能够在学习时计时，计时结束后自动关联到知识点卡片，并基于 FSRS 算法预测最佳复习时间。

### 1.1.2 可行性分析

- **技术可行性**：Rust 语言生态成熟（Iced GUI 框架、Clap CLI 框架、FSRS 算法库），JSON 文件存储无需外部数据库依赖，单机可运行
- **操作可行性**：同时提供 CLI 和 GUI 两种操作方式，满足不同用户偏好
- **经济可行性**：完全开源，零成本部署

### 1.1.3 需求分析

**功能需求：**
1. 树形知识分类管理，支持多级文件夹和卡片
2. 学习计时器，支持启动/暂停/停止，计时精度到毫秒
3. 计时记录与知识卡片的关联，支持记忆质量评价
4. 基于 FSRS 算法的复习预测与急迫度计算
5. 待办事项管理，支持优先级、截止日期、标签和 ICS 导入/导出
6. 日程管理，支持重复规则和 ICS 格式
7. Obsidian 知识库导入
8. 预设系统，支持自定义 FSRS 参数训练

**非功能需求：**
1. 数据通过 JSON 文件持久化，确保程序重启后数据不丢失
2. CLI 命令响应时间不超过 500ms
3. GUI 界面响应式布局，秒级计时更新

## 2.2 系统详细设计

### 2.2.1 CLI 命令行模块详细设计（starry）

**功能描述：** 基于 Clap 框架的命令行工具，支持 8 大命令组共 18 个子命令。所有命令共享同一 DataFs 数据层。

**命令结构：**

```
tmd
├── init                          # 初始化数据目录
├── tree create --name <NAME>     # 创建知识树（支持从 Obsidian 导入）
├── tree list [name]              # 列出知识树或树内卡片
├── card create --path <PATH>     # 创建卡片
├── card list --path <PATH>       # 列出卡片
├── card predict --path <PATH>    # 查看卡片预测信息
├── card link --timer --path --quality  # 关联计时到卡片
├── preset create --name <NAME>   # 创建预设
├── preset list [name]            # 列出预设
├── preset train --name <NAME>    # 训练预设
├── timer start/stop/pause/get    # 计时器操作
├── todo create/list/complete/delete  # 待办管理
├── schedule create/list          # 日程管理
└── review list [urgency]         # 按急迫度查看复习列表

### 2.2.5 FSRS 复习预测算法详细设计（starry）

**算法流程：**

```
┌─────────────────────────────────────────────────────────┐
│               FSRS 预测流程                               │
│                                                         │
│  输入: review_records, current_memory_state,             │
│        desired_retention (默认 0.9)                       │
│    │                                                    │
│    ▼                                                    │

│    │                                                    │
│    ├── Yes → FSRS::next_states(None, 0.9, 0)            │
│    │         → 返回初始 MemoryState                     │
│    │                                                    │
│    └── No → 遍历 records:                               │
│              for i in 0..records.len() {                │
│                days_elapsed = 距上次天数                 │
│                next_states = engine.next_states(         │
│                  memory_state, 0.9, days_elapsed)        │
│                memory_state = match record.quality {     │
│                  Relearn → again.memory                  │
│                  Hard → hard.memory                      │
│                  Good → good.memory                      │
│                  Easy → easy.memory                      │
│                }                                        │
│              }                                          │
│    │                                                    │
│    ▼                                                    │
│  days_since_last = 距最后记录天数                         │
│  next_states = engine.next_states(                      │
│    memory_state, 0.9, days_since_last)                  │
│    │                                                    │
│    ▼                                                    │
│  输出: (next_review, memory_state)                      │
│  next_review = Utc::now() + days(interval)              │
│                                                         │
└─────────────────────────────────────────────────────────┘

2. **FSRS 间隔重复集成**：将行业领先的 FSRS v5 算法集成到时间管理系统中，实现科学复习规划
3. **计时-关联-预测闭环**：从学习计时到卡片关联到复习预测的完整工作流，消除数据孤岛
4. **ICS 标准支持**：待办和日程支持 iCalendar 标准格式导入/导出，可与其他日历工具互通
5. **Obsidian 生态整合**：支持从 Obsidian Vault 直接导入知识结构，降低迁移成本
6. **预设训练系统**：支持基于历史复习数据训练自定义 FSRS 参数，实现个性化预测

## 5.5 本章小结

本章对时间管理器系统的整体情况进行了说明。代码总计约 3600+ 行，覆盖 CLI、GUI、数据持久化、FSRS 算法、Timer 管理、Obsidian 导入等多个模块。系统可通过 `cargo build --release` 发布，支持通过环境变量和配置文件自定义运行参数。

# 第 6 章 总结

## 1. 全文总结

本课程设计完成了时间管理器（TimeManager）系统的设计与实现。系统旨在解决知识工作者的时间追踪与复习管理需求，将计时工具和间隔重复算法整合为统一的解决方案。

系统采用 Rust 语言开发，通过四层架构（数据持久化层、核心业务层、接口层、用户界面层）实现了 CLI 和 GUI 双界面共享数据存储的设计。CLI 工具支持 8 大命令组共 18 条子命令，GUI 桌面应用包含 7 个功能完整的标签页。

在技术实现方面，系统集成了 FSRS v5 间隔重复算法实现科学复习预测；采用 JSON 文件系统实现无外部依赖的轻量级数据持久化；通过有限状态机管理计时器生命周期；支持 iCalendar 标准格式实现与其他日历工具的互通。

在实际应用效果方面，系统可以有效帮助用户追踪学习时间投入、规划科学复习计划，实现学习效率的可量化管理。

目前系统存在以下不足：GUI 界面在视觉设计上仍有优化空间；尚不支持云同步功能；移动端适配尚未实现。

## 2. AI 辅助编程对完成项目的帮助及影响

**积极影响：**
- AI 编程助手在代码生成、错误调试和重构方面显著提高了开发效率
- 减少了查阅文档的时间，特别是在 Iced GUI 框架和 FSRS 算法的集成过程中
- 帮助快速生成测试用例框架，提高了测试覆盖率

**负面影响：**
- 过度依赖 AI 生成代码可能导致对底层原理理解不足
- AI 生成的代码有时需要人工审查和调整，特别是类型安全和错误处理方面
- 需要培养判断 AI 生成代码质量的能力，避免引入潜在问题

总体而言，AI 辅助编程在提升效率方面效果显著，但对开发者自身的架构设计能力和代码审查能力提出了更高要求。
